# 评论接入可行性与实现范围

初次检查：2026-09-23；接入更新：2026-09-24。

初次评估覆盖当时尚未接入评论输出的 14 个平台，其中实测可行的 11 个现已接入。B站、微博、小红书和百度贴吧已经实现，不重复评估。按照本次需求，能取得有效评论即视为可接入热评功能，不强制要求热度或点赞排序；实际采用的热门、精选、默认或时间顺序仍应保留。

“已接入”表示生产解析器、配置开关和评论展示已实现，且通过匿名请求或复用本项目已有访客会话、签名取得了非空评论；不保证所有作品均可读取。关闭评论、内容权限、接口风控和网络环境仍会影响单条链接。HTTP 200 空响应、只有评论总数或只有接口名称，不作为成功证据。

## 结果总览

初次评估的 14 个平台中，11 个已实现评论输出，3 个仍需额外访问条件或接口证据。加上当时已有的 4 个平台，初次接入完成时共 15 个平台支持热评输出；后续平台陆续接入，现已包括网易云音乐和喜马拉雅在内，共有 25 个平台评论开关。

## 已接入的数据来源

### 抖音

- 可复用本项目已有的 `a_bogus` 签名和匿名 `ttwid` 会话读取评论，无需先引入账号 Cookie 配置。
- 已验证接口为 `GET https://www.douyin.com/aweme/v1/web/comment/list/`，使用作品 `aweme_id`、`cursor`、`count` 等参数并附加与当前 UA 一致的签名。
- 公开视频 `7525538910311632128` 已取得 10 条真实评论，响应总数 98，并返回下一页游标。
- 无签名的候选路线返回 HTTP 200 空内容，不能代替已验证的签名路线。排序优先遵循接口默认顺序，不能把一页评论重新排序后称为全站最热。
- 维护重点是签名、访客会话、游标及接口风控，接入成本中等。

### AcFun

- 匿名 `/rest/pc-direct/comment/list` 返回结构化 `hotComments` 和 `rootComments`，可优先使用热评，没有热评时读取普通根评论。
- 样例 `ac17006103` 已返回 4 条明确热评，其中最高点赞数为 199。
- 可以复用现有内容 ID；需要按不同内容类型核对评论接口的资源类型参数，不能只验证视频后就承诺番剧与动态全部可用。

### 闲鱼

- 当前商品移动前端使用 `mtop.taobao.idle.comment.list`，版本 `5.0`，参数包括 `bizType=0`、`itemId`、`pageNumber`、`roesPerPage`；最后一个参数按接口实际拼写传入。
- 可复用项目现有 MTop 访客令牌和请求签名，不需要用户账号 Cookie。商品 `1041851462577`、`960835490814` 各返回 3 条有效留言。
- 响应包含 `items`、留言正文、打码昵称、`reportTime` 及 `superFavorInfo.superFavorNum`，可映射为现有评论结构。没有验证独立的热门排序，保留接口原始顺序即可。
- 某个旧商品虽返回成功和非零总数，`items` 却为空，不能据总数制造评论。商品失效、留言不可见及 MTop 风控要与真实零评论区分。
- 请求 10 条实际只返回 3 条；第二件商品虽返回 `nextPage=true`，第二页却为空。当前前端也只展示前三条并引导到 App 查看更多，因此只确认少量公开留言可读，不承诺完整分页或任意条数。

### 今日头条

- 当前移动前端调用 `https://api.toutiaoapi.com/article/v4/tab_comments`，使用 `group_id`、`tab_index=0`、`aid=13`、`count`、`offset`。
- 近期文章 `7688204480379011619` 匿名取得 10 条评论；`www.toutiao.com/article/v4/tab_comments` 同样取得有效结果，不需要账号 Cookie 或新增签名。
- 页面状态中的 `commentList` 为 `null`，因此不能只解析现有状态树，需要额外请求评论接口。
- 接入阶段补充验证了视频和微头条：微头条 `1876999327989760` 与视频 `7658126948590583849` 各取得 25 条，视频 `7673699270804815906` 取得 9 条。三类入口均通过完整 `parse()`，优先使用前端 `sessionConfig.groupId`，再读取 `articleInfo.gid` 等字段确定评论资源。

### 小黑盒

- 现有 `_fetch_signed_api` 可以直接用于 `/bbs/app/link/tree`。正文当前使用的仅楼主参数不能原样用于取评论。
- 帖子 `191151186`，使用 `owner_only=0`、`is_first=1`、`page=1`、`index=1`、`limit=20`，已返回 20 楼评论，总计 279 楼、14 页。
- 返回的排序菜单明确提供 `hot`（热门）、`time_aes`（正序）、`time_desc`（倒序），样例前几条点赞数为 2693、1133、868。
- PC 游戏评价已另外验证：当前网页使用 `/bbs/app/link/game/comments`，以 `appid=730`、`offset=0`、`limit=5`、`api_version=4`、`sort_type=4` 取得 5 篇真实评价，首篇点赞数为 7428。
- 游戏评价排序选项为 `0=推荐`、`1=最新`、`4=有用`、`3=欢乐`。评价位于 `links`，可读取 `linkid`、`description`、`up`、`create_at`、`user`。帖子楼中楼需与独立主评论区分；接入阶段已验证 BBS 与 PC 游戏各 25 条跨页数据，主机与手游评价未接入。

### 雪球

- 可复用当前解析器的匿名访客令牌，不必新增用户登录配置。
- `api.xueqiu.com/statuses/comments_excellent.json?id=410373625` 已返回 2 条精选评论，点赞数为 4、3；普通 `comments.json` 已返回 10 条评论。两者响应的 `count` 分别为 6、15，不能把该总数字段当成本次实际取得的条数。
- 精选为空时可以读取普通评论。需维持现有访客令牌失效处理，并分别核对精选和普通列表的分页字段。

### 知乎

- 评论接口 `/api/v4/comment_v5/{answers|articles}/{id}/root_comment?order=score` 可复用现有匿名 `d_c0` 会话和 `x-zse-96` 签名。
- 不携带所需签名的请求返回 HTTP 403；复用现有签名后，3 条回答分别取得 7、3、10 条评论，1 篇专栏取得 10 条评论。
- 已取得明确热门标记和点赞字段。样例中的前几条热门评论点赞数为 1040、621、509、471、399。
- 部分有效内容的评论列表为空，必须将零评论与接口失败区分。回答与文章的评论资源类型不同，均需单独接入和验证。
- 回答 `603370131`、专栏文章 `618321077` 已分别验证首、次页各 10 条，分页间没有重复。后续请求应使用接口给出的 `paging.next` 游标，并按实际路径与查询串重新签名。

### V2EX

- 匿名旧接口 `https://www.v2ex.com/api/replies/show.json?topic_id={主题ID}` 返回回复 ID、作者、正文和发布时间，按楼层排序；响应不含感谢数，实测分页参数无效，解析器只请求一次。
- 公开主题网页 JSON-LD 提供评论感谢统计。开启评论时最多读取前 5 页（每页最多 100 楼），将回复 ID、作者与时间和匿名接口结果对齐，在已取得范围内优先展示感谢数较多的评论，其余按楼层补齐。
- 网页不可用或没有获感谢的评论时，降级为匿名接口的楼层顺序评论。感谢数通过现有 `likes` 字段展示，未知时省略，不填 `0`；不能把有限页面内排序称为官方热评或全帖热度排名。
- 复用全局评论数量与 `message.hot_comments.v2ex` 开关，默认数量为 `0`；关闭评论或仅输出富媒体时不请求回复和感谢统计。评论失败保留主帖，不新增 Cookie、Token、代理或浏览器依赖。

### TikTok

- 匿名 `/api/comment/list` 已取得同一公开视频两页各 10 条评论，响应状态为成功，并含 `sort_tags.top_list` 等标记。
- 样例作品 `6718335390845095173` 使用 `aid=1988`、`aweme_id`、`cursor`、`count=10`，实测未携带登录 Cookie 或额外签名。
- 当前列表不是单纯的时间或点赞降序；按本次要求，可以保留平台默认顺序。
- 接入需处理评论游标、表情或图片占位，以及地区和风控造成的空响应；不能将匿名样例成功推广为所有地区和作品均可读取。

### YouTube

- 现有解析器已经读取观看页，可以进一步利用 `ytInitialData` 中真实评论菜单的 continuation 和页面提供的 WEB 客户端上下文。
- 样例 `jNQXAC9IVRw` 的菜单明确提供 `Top` 和 `Newest`。匿名调用 `POST /youtubei/v1/next` 的 Top 入口后取得 20 条评论。
- 当前响应使用 `commentThreadRenderer` 引用评论实体，正文、作者和互动信息位于 `frameworkUpdates` 下的 `commentEntityPayload`，不能仅查找旧式 `commentRenderer`。
- 样例赞数显示为 `4.8M`，时间显示为 `6 years ago`；这些不是精确点赞整数或绝对时间，映射现有字段时需要明确精度限制。
- 无需新增用户凭据即可尝试内置接口，但属于非公开稳定协议。官方替代方案是 [YouTube Data API 的 commentThreads.list](https://developers.google.com/youtube/v3/docs/commentThreads/list)，支持 `order=relevance/time`，需要额外 API 凭据与额度。

### Steam

- 当前游戏详情接口不包含评测列表，但可以根据已有 appid 使用 [Steam 官方用户评测接口](https://partner.steamgames.com/doc/store/getreviews)。
- 匿名 `https://store.steampowered.com/appreviews/570?json=1&filter=all&language=schinese&day_range=365&num_per_page=3&purchase_type=all` 已返回 3 条中文玩家评测，点赞数为 319、118、96。
- 响应包含作者 Steam ID、昵称、正文、时间和 `votes_up`，适合直接映射现有热评结构。
- `filter=all` 按有用程度和时间窗口选取；也可以使用 `recent` 或 `updated`。这类内容属于游戏评测，应保留其含义。
- 接入成本低，可复用 Steam 的解析代理；启用小黑盒游戏详情来源时，仍可凭 appid 独立读取 Steam 评测。

### Pixiv

- 接口为 `https://www.pixiv.net/ajax/illusts/comments/roots?illust_id={id}&offset=0&limit=10`。公开日榜作品 `149905913` 已匿名取得两页共 19 条评论，其中 7 条文字、12 条贴纸，分页间没有重复。
- 列表按时间倒序，未验证热门排序；按本次要求仍属于可接入范围。
- 贴纸不能因没有文字而被误判为空评论，可转换为文字占位。点赞信息缺失时不可推断评论热度。

## 需要额外条件或仍未验证成功的路线

### 快手

- 有已知评论端点 `POST https://www.kuaishou.com/rest/v/photo/comment/list`，请求包含 `photoId` 和 `pcursor`；公开客户端使用登录浏览器会话，响应模型包含 `rootCommentsV2` 和 `pcursorV2`。
- 样例作品 `3x3zxz4mjrsc8ke` 的移动分享页面可以匿名读取，但只有评论数量，没有评论正文。
- REST、旧 GraphQL 和移动评论端点的匿名请求均未得到评论；建立当次匿名访客会话后进一步返回业务码 `400002` 和验证码信息。
- 当前证据只能说明本环境匿名链路尚未打通，不能断言“必须登录”或“接口不可用”。正常授权会话下的评论请求仍有研究价值，但需要另行验证其认证与风控条件。

### 微信

- **公众号文章**：匿名页面可取得 `comment_id`，但精选留言接口返回 `base_resp.ret=-3`、`errmsg=no session`。当前文章解析路线不具备读取留言所需的微信会话，不能仅凭文章正文可读就承诺评论可读。
- **视频号**：现有公开预览前端的评论入口引导到微信内，未找到已验证可匿名读取评论列表的公开预览接口。现有元宝换取的视频预览凭据不能未经验证就视为评论访问凭据。
- 公众号存在有条件接入的可能；视频号还需要新的有效接口和会话证据。本次未使用用户私人登录态验证。

### Twitter/X

- 当前 FxTwitter 主帖接口实测正常，但 `replies` 仅表示回复数量，不提供回复正文列表；现有 Guest GraphQL 的 `TweetResultByRestId` 也不是评论列表接口。
- [X 官方搜索接口](https://docs.x.com/x-api/posts/search/introduction)可按会话检索回复，支持 `sort_order=recency/relevancy`，需要开发者应用及认证。近期搜索仅覆盖最近 7 天，全量历史搜索有额外访问和计费条件。
- 匿名访问官方近期搜索端点实测 HTTP 401 Unauthorized。官方认证路线有条件可行，但当前无凭据解析方案没有已验证的回复数据源。
- 若接入会话搜索，还需区分直接回复与嵌套回复，避免将整条会话里的其他分支错误归属给输入推文。

## 实现范围与验证

- 所有新增平台使用 `message.hot_comments.count` 和各自平台开关；默认数量为 0，关闭平台热评或选择仅富媒体时不请求评论。
- AcFun 只接入普通视频投稿评论，番剧和动态的评论资源映射尚未接入。小黑盒覆盖 BBS 主评论和 PC 游戏评价，不展开楼中楼、主机与手游评价。
- Steam 优先取过去一年内中文有用评测，不足时补充所有语言的近期评测；游戏详情委托小黑盒时，评论仍从 Steam 获取。
- 11 个新增平台均通过完整 `parse()` 在线验证，取得正文与评论；抖音、TikTok、AcFun、头条、小黑盒、知乎、YouTube 和 Pixiv 另验证跨页数据。配置测试覆盖 15 个平台的数量、开关和输出模式，平台测试覆盖去重、分页终止、失败保留正文及取消传播。另用本地 HTTP 与消息组件桩验证真实配置工厂、YouTube/Pixiv 解析、解析结果归一化、消息节点分片和 ZIP 归档，确认长评论、缩写赞数、未知点赞与贴纸不丢失；未验证 AstrBot 内实际消息发送。
- 本次功能归入尚未发布的 `1.7.0`，没有重复递增版本号；快手、微信和 Twitter/X 未新增评论开关或实现；GitHub 仓库概况也不提供评论输出。

## 接入约束

- 复用现有 `hot_comments` 元数据与消息构建逻辑，按平台增加热评开关和 `hot_comment_count` 参数；条数为 `0` 或仅输出富媒体时不额外请求评论。
- 有热门或精选列表时优先使用；缺少该排序时允许普通评论，保留来源顺序。不要把少量已抓取评论中的点赞排序称为完整的全站热度排名。
- 按评论 ID 去重并限制请求数量；附加评论失败不影响已成功解析的正文和媒体，取消操作必须继续向上传播。
- 匿名路线失败的平台不默认引入登录态、浏览器自动化或额外服务；这些属于需要单独确定的实现前提。
- 调研响应与脚本保存在被忽略的 `test/hot_comment_probe/` 中，不加入 Git 跟踪。本报告同时记录初次接口证据与本次接入范围；后续收尾也已将贴吧接口回退的普通回复纳入热评输出，遵循相同的评论口径。
